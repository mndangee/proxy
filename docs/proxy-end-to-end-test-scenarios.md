# DataForge 프록시 기능 최종 테스트 시나리오

## 테스트 목적

다음 기능이 실제 프로젝트 환경에서 안전하게 동작하는지 확인합니다.

- 프로젝트 서버 없이 저장된 더미 응답만 사용
- 실행 중인 프로젝트 서버의 포트 전환
- 저장된 응답과 실제 서버 응답 분기
- 연결 실패 시 기존 서버 자동 복구
- 연결 해제 및 앱 종료 시 원래 포트 복구
- 최근 요청 기록, API 상세 이동 및 기록 유지

## 테스트 기준 환경

| 항목 | 값 |
| --- | --- |
| 프로젝트 요청 포트 | `7777` |
| 프로젝트 서버 이동 포트 | `7778` |
| 더미 서버 내부 포트 | `4780` |
| 프로젝트 서버 폴더 | `/Users/minhyee/git/care/server` |
| 테스트 페이지 | `http://localhost:7777/care/mobile/service/mobility/index.html?state=MvmtMain` |

다른 값을 사용하는 경우 문서의 포트와 경로를 실제 환경에 맞게 바꿔서 진행합니다.

## 시작 전 확인

1. DataForge 앱을 완전히 종료합니다.
2. 프로젝트 서버도 종료합니다.
3. 아래 명령으로 세 포트가 비어 있는지 확인합니다.

```bash
lsof -nP -iTCP:7777 -iTCP:7778 -iTCP:4780
```

아무 결과도 나오지 않으면 정상입니다. 프로세스가 표시되면 어떤 서버인지 확인하고 정상적인 방법으로 종료합니다.

4. 최신 코드로 DataForge를 다시 실행합니다.

```bash
npm run dev
```

## P-01. 프로젝트 서버 없이 더미 응답만 연결

### 실행

1. DataForge에서 `더미 응답 연결`을 엽니다.
2. `현재 서버 포트`에 `7777`을 입력합니다.
3. `추가 설정`을 엽니다.
4. 다음 값을 확인합니다.
   - 서버 이동 포트: `7778`
   - 더미 서버 내부 포트: `4780`
   - 실행 중인 프로젝트 서버 자동 연결: 끔
5. `연결 시작`을 누릅니다.

### 예상 결과

- [ ] 연결이 오류 없이 완료된다.
- [ ] 상태 카드에 연결이 정상이라고 표시된다.
- [ ] 프로젝트 서버가 없으므로 저장된 더미 응답만 사용할 수 있다는 설명이 표시된다.
- [ ] `7777`과 `4780` 포트가 열려 있다.
- [ ] `7778` 포트는 비어 있다.

```bash
lsof -nP -iTCP:7777 -iTCP:7778 -iTCP:4780
```

### 요청 확인

저장된 트랜을 호출할 수 있는 기능을 실행합니다.

- [ ] 저장된 트랜은 정상 응답한다.
- [ ] 최근 요청에 트랜 ID가 표시된다.
- [ ] 처리 결과가 `더미 응답`으로 표시된다.
- [ ] 저장되지 않은 트랜은 실제 서버가 없으므로 실패한다.

### 정리

`연결 끊기`를 누르고 세 포트가 정리됐는지 확인합니다.

## P-02. 입력값 검증

각 항목을 하나씩 테스트하고 다음 항목으로 넘어가기 전에 정상값으로 되돌립니다.

### 현재 서버 포트 오류

1. 현재 서버 포트에 `7777abc`를 입력합니다.
2. `연결 시작`을 누릅니다.

- [ ] 연결이 시작되지 않는다.
- [ ] 현재 서버 포트만 오류 상태로 표시된다.
- [ ] 1~65535 사이의 값을 입력하라는 해결 방법이 표시된다.

`0`, `65536`, 빈 값도 동일하게 확인합니다.

### 포트 중복

1. 현재 서버 포트와 서버 이동 포트를 모두 `7777`로 설정합니다.
2. `연결 시작`을 누릅니다.

- [ ] 추가 설정이 자동으로 열린다.
- [ ] 세 포트 입력이 모두 오류 상태로 표시된다.
- [ ] 서로 다른 포트를 사용하라는 설명이 표시된다.

테스트 후 `7777 / 7778 / 4780`으로 되돌립니다.

### 서버 폴더 미입력

1. 자동 연결을 켭니다.
2. 서버 코드 폴더를 비웁니다.
3. `연결 시작`을 누릅니다.

- [ ] 서버 코드 폴더만 오류 상태로 표시된다.
- [ ] 서버 폴더를 선택하라는 해결 방법이 표시된다.

## P-03. 실행 중인 서버 전환 취소

### 준비

별도 터미널에서 프로젝트 서버를 `7777`로 실행합니다.

```bash
cd /Users/minhyee/git/care/server
node dummy.server.js
```

브라우저에서 테스트 페이지가 정상적으로 열리는지 확인합니다.

### 실행

1. DataForge 프록시 설정에서 자동 연결을 켭니다.
2. 서버 코드 폴더로 `/Users/minhyee/git/care/server`를 선택합니다.
3. 감지된 실행 방법이 표시되는지 확인합니다.
4. `연결 시작`을 누릅니다.
5. 서버 종료 확인 모달에서 `취소`를 누릅니다.

### 예상 결과

- [ ] 운영체제 시스템 확인창이 아니라 DataForge 공통 모달이 표시된다.
- [ ] PID, 실행 폴더, 명령이 표시된다.
- [ ] 취소 후 DataForge 연결이 시작되지 않는다.
- [ ] 기존 프로젝트 서버가 계속 `7777`을 사용한다.
- [ ] 테스트 페이지가 계속 정상적으로 열린다.

## P-04. 실행 중인 서버 전환 승인

P-03 상태에서 다시 진행합니다.

1. `연결 시작`을 누릅니다.
2. 확인 모달에서 `종료하고 전환`을 누릅니다.
3. 최대 10초 동안 연결 완료를 기다립니다.

### 예상 결과

- [ ] 확인 모달이 중복으로 나타나지 않는다.
- [ ] DataForge가 `7777`을 사용한다.
- [ ] 프로젝트 서버가 `7778`로 이동한다.
- [ ] 더미 서버가 `4780`을 사용한다.
- [ ] 상태 카드에 `API 연결 정상`이 표시된다.
- [ ] 테스트 페이지가 기존 주소 `localhost:7777`에서 정상적으로 열린다.

```bash
lsof -nP -iTCP:7777 -iTCP:7778 -iTCP:4780
```

## P-05. 더미 응답과 실제 서버 전달

P-04의 정상 연결 상태에서 진행합니다.

### 저장된 트랜

1. DataForge에 저장된 트랜을 호출합니다.
2. 최근 요청 패널을 엽니다.

- [ ] 트랜 ID가 정확히 표시된다.
- [ ] 결과가 `더미 응답`이다.
- [ ] 상태 코드와 응답 시간이 표시된다.
- [ ] 응답 라벨이 있으면 함께 표시된다.
- [ ] 항목을 누르면 해당 API 상세 화면으로 이동한다.

### 저장되지 않은 트랜

1. DataForge에 저장되지 않은 트랜을 호출합니다.
2. 최근 요청 패널을 확인합니다.

- [ ] 결과가 `실제 서버`이다.
- [ ] 프로젝트 화면의 기존 기능이 정상적으로 동작한다.
- [ ] 동일 요청이 중복 기록되지 않는다.

## P-06. 쿼리 파라미터별 응답 선택

동일 API에 기본 응답과 쿼리 조건 응답이 등록돼 있을 때 진행합니다.

1. 조건 없는 요청을 호출합니다.
2. 기본 응답이 반환되는지 확인합니다.
3. 등록한 쿼리 파라미터를 포함해 같은 API를 호출합니다.
4. 조건 응답이 반환되는지 확인합니다.
5. 일치하지 않는 값을 전달합니다.

### 예상 결과

- [ ] 조건이 없으면 Default 응답이 선택된다.
- [ ] 모든 쿼리 조건이 일치하면 해당 조건 응답이 선택된다.
- [ ] 조건이 여러 개 일치하면 조건 개수가 많은 응답이 우선한다.
- [ ] 조건이 맞지 않는 응답은 기본 응답 후보로 사용되지 않는다.
- [ ] 최근 요청에 실제 사용된 응답 라벨이 표시된다.

## P-07. 연결 중 중복 실행 및 닫기 방지

3. 연결 처리 중 닫기 버튼을 누릅니다.
4. 팝업 바깥 영역도 누릅니다.

### 예상 결과

- [ ] 연결 작업은 한 번만 실행된다.
- [ ] 프로젝트 서버 프로세스가 중복 실행되지 않는다.
- [ ] 확인 모달이 중복으로 나타나지 않는다.
- [ ] 연결 처리 중에는 팝업이 닫히지 않는다.
- [ ] 연결 성공 또는 실패 후에는 정상적으로 닫을 수 있다.

## P-08. 잘못된 실행 명령과 자동 복구

### 준비

프로젝트 서버가 `7777`에서 정상 실행 중이어야 합니다.

### 실행

1. 자동 연결을 켭니다.
2. 정상 서버 폴더를 선택합니다.
3. 감지된 실행 방법을 아래처럼 변경합니다.

```text
node nonexistent-server.js -port {{port}}
```

4. `연결 시작`을 누릅니다.
5. `종료하고 전환`을 누릅니다.

### 예상 결과

- [ ] 연결 실패가 구조화된 오류 카드로 표시된다.
- [ ] 제목, 발생 상황, 해결 방법이 분리돼 있다.
- [ ] 실행 방법 입력만 오류 상태로 표시된다.
- [ ] `기술 정보 보기`에서 실제 오류를 확인할 수 있다.
- [ ] 기존 프로젝트 서버가 `7777`로 자동 복구된다.
- [ ] 테스트 페이지가 다시 정상적으로 열린다.

```bash
lsof -nP -iTCP:7777 -sTCP:LISTEN
```

테스트 후 올바른 실행 명령으로 되돌립니다.

## P-11. 최근 요청 기록 유지와 삭제

1. 더미 요청과 실제 서버 요청을 여러 개 발생시킵니다.
2. 최근 요청 패널을 열었다가 닫습니다.
3. DataForge를 완전히 종료하고 다시 실행합니다.

### 예상 결과

- [ ] 최근 요청 기록이 유지된다.
- [ ] 이미 확인한 요청은 새 요청 배지로 다시 표시되지 않는다.
- [ ] 새 요청이 발생하면 읽지 않은 요청 수가 표시된다.
- [ ] 패널을 열면 배지가 사라진다.
- [ ] 기록은 오늘·어제·날짜별로 묶여 있다.

`기록 지우기`를 누릅니다.

- [ ] 시스템 확인창이 아니라 DataForge 공통 모달이 표시된다.
- [ ] 취소하면 기록이 유지된다.
- [ ] 확인하면 화면과 저장 파일의 기록이 모두 삭제된다.
- [ ] 앱을 다시 실행해도 삭제한 기록이 나타나지 않는다.

## 최종 통과 기준

다음 조건을 모두 만족하면 프록시 기능 테스트를 통과한 것으로 판단합니다.

- [ ] 프로젝트 서버가 없어도 저장된 더미 응답을 사용할 수 있다.
- [ ] 기존 프로젝트 서버를 안전하게 `7777 → 7778`로 전환할 수 있다.
- [ ] 더미가 없으면 실제 프로젝트 서버로 전달된다.
- [ ] 연결 실패 시 기존 서버가 `7777`로 복구된다.
- [ ] 연결 해제와 앱 종료 시 원래 서버가 복구된다.
- [ ] 중복 클릭이나 팝업 닫기로 연결 작업이 중복·중단되지 않는다.
- [ ] 오류 원인과 해결 방법을 사용자가 확인할 수 있다.
- [ ] 최근 요청 기록과 API 상세 이동이 정상적으로 동작한다.

## 문제 기록 양식

문제가 발생하면 아래 양식을 복사해 작성합니다.

```text
시나리오 번호:
실행한 단계:
예상 결과:
실제 결과:
오류 카드 제목:
기술 정보:
재현 여부: 항상 / 가끔 / 한 번
UI 관련 의견:
```

포트 상태도 함께 기록합니다.

```bash
lsof -nP -iTCP:7777 -iTCP:7778 -iTCP:4780
```
