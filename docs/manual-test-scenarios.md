# DataForge 통합 테스트 시나리오

## 1. 테스트 목적

프로젝트 가져오기부터 더미 응답 선택, 프로젝트 서버 자동 전환, 연결 진단, 서버 복구까지 사용자의 전체 흐름이 macOS와 Windows에서 정상 동작하는지 확인한다.

## 2. 공통 준비

- DataForge 최신 개발 빌드
- 테스트용 프로젝트 서버
- 테스트용 JSON 응답 폴더
- 더미가 등록된 API 1개
- 더미가 등록되지 않은 실제 API 1개
- 쿼리 조건 응답이 등록된 API 1개
- 사용 가능한 포트 3개
  - 현재 서버 포트: `7777`
  - 서버 이동 포트: `7778`
  - DataForge 내부 포트: `4780`
- 테스트 전 중요한 서버 작업은 저장한다.

테스트 서버에는 가능하면 아래 요청을 준비한다.

| 요청 | 용도 |
|---|---|
| `GET /api/mock-target` | DataForge 더미 응답 확인 |
| `GET /api/real-target` | 실제 서버 전달 확인 |
| `GET /api/query-target?type=test` | 쿼리 조건 응답 확인 |

## 3. 기본 실행

### TC-001 앱 실행

1. 개발 환경에서 `npm run dev`를 실행한다.
2. 홈 화면이 표시되는지 확인한다.
3. 프로젝트 목록, `프로젝트 가져오기`, `더미 응답 연결` 버튼을 확인한다.

기대 결과:

- 앱이 오류 없이 열린다.
- 콘솔에 앱 실행을 중단시키는 오류가 없다.
- 홈 화면의 버튼을 클릭할 수 있다.

## 4. 프로젝트 가져오기

### TC-101 서버 더미 폴더 가져오기

1. 홈에서 `프로젝트 가져오기`를 누른다.
2. 안내 문구를 확인한다.
3. `파일·폴더 선택`을 누르고 테스트 JSON 폴더를 선택한다.

기대 결과:

- 별도 확인 단계 없이 바로 가져오기가 실행된다.
- 가져오기 후 홈 화면에 그대로 남는다.
- 프로젝트 목록이 즉시 갱신된다.
- 완료 안내에 프로젝트명, API 수, 응답 수, 제외 파일 수가 표시된다.
- `가져온 데이터 보기`를 눌렀을 때만 프로젝트 페이지로 이동한다.

### TC-102 동일 트랜 응답 분류

다음과 같은 파일을 함께 가져온다.

```text
VD_CMDJ0089_1080_Default.json
VD_CMDJ0089_1081_Test.json
VD_CMDJ0089_1082_Error.json
```

기대 결과:

- 하나의 `VD.CMDJ0089` API로 등록된다.
- Default, Test, Error 응답이 각각 한 개씩 생성된다.
- 파일명의 숫자는 동일 트랜 내 응답을 구분하는 데 사용된다.
- 명시적인 라벨이 없는 경우 sourceId가 가장 빠른 응답이 Default가 된다.

### TC-103 가져오기 예외

각 항목을 별도로 확인한다.

- JSON이 없는 폴더
- 손상된 JSON 파일
- 지원하지 않는 ZIP
- 이미 존재하는 프로젝트 이름
- 파일 선택 취소

기대 결과:

- 앱이 멈추거나 종료되지 않는다.
- 취소는 오류로 표시되지 않는다.
- 실패한 경우 사용자가 이해할 수 있는 원인이 표시된다.
- 원본 파일은 변경되지 않는다.

## 5. 응답 선택

### TC-201 기본 응답

1. 하나의 API에 Default, Test, Error 응답을 등록한다.
2. Default 응답을 활성화한다.
3. 쿼리 조건 없이 API를 호출한다.

기대 결과:

- Default 응답이 반환된다.
- 응답 레이블의 글자 크기가 테이블의 다른 글자와 어울린다.

### TC-202 쿼리 파라미터 응답

1. Test 응답에 `type=test` 조건을 등록한다.
2. Error 응답에 `type=error` 조건을 등록한다.
3. 다음 요청을 차례로 보낸다.

```text
/api/query-target
/api/query-target?type=test
/api/query-target?type=error
/api/query-target?type=unknown
```

기대 결과:

- 조건 없는 요청은 Default 응답을 사용한다.
- `type=test`는 Test 응답을 사용한다.
- `type=error`는 Error 응답을 사용한다.
- 일치하지 않는 조건은 조건부 응답을 임의로 선택하지 않고 Default로 처리한다.

### TC-203 복수 쿼리 조건

1. 응답에 `type=test`, `user=1` 두 조건을 등록한다.
2. 두 조건이 모두 있는 요청과 하나만 있는 요청을 보낸다.

기대 결과:

- 모든 조건이 일치할 때만 해당 응답이 선택된다.
- 일부 조건만 일치하면 Default 응답을 사용한다.

## 6. 최초 사용자 안내

### TC-301 최초 노출

1. 브라우저 저장 데이터에서 `dataforge-proxy-guide-dismissed-v1`을 제거한다.
2. `더미 응답 연결` 화면을 연다.

기대 결과:

- 3단계 사용 안내가 자동으로 표시된다.
- `나중에`와 `다시 보지 않기` 버튼의 너비가 같다.
- 두 버튼 모두 공통 버튼 스타일로 선명하게 보인다.

### TC-302 안내 닫기

1. `나중에`를 누르고 화면을 닫았다가 다시 연다.
2. `다시 보지 않기`를 누르고 화면을 닫았다가 다시 연다.
3. 우측 상단 `사용 방법`을 누른다.

기대 결과:

- `나중에`를 선택하면 다음 진입 시 다시 표시된다.
- `다시 보지 않기`를 선택하면 자동 표시되지 않는다.
- `사용 방법`을 누르면 언제든 다시 볼 수 있다.

## 7. 자동 연결 정상 흐름

### TC-401 실행 방법 자동 감지

각 패키지 매니저 프로젝트에서 서버 코드 폴더를 선택한다.

- `package-lock.json`
- `pnpm-lock.yaml`
- `yarn.lock`
- `bun.lock` 또는 `bun.lockb`
- `dummy.server.js`

기대 결과:

- `dev`, `start`, `serve` 순서로 실행 스크립트를 찾는다.
- 올바른 패키지 매니저와 명령이 `감지된 실행 방법`에 표시된다.
- Vite, Nuxt, Next의 포트 실행 옵션이 자동으로 구성된다.
- 사용자가 실행 명령을 직접 입력하지 않아도 된다.

### TC-402 기존 서버 자동 전환

1. 테스트 서버를 `7777` 포트로 실행한다.
2. DataForge에서 현재 서버 포트 `7777`, 서버 이동 포트 `7778`, 내부 포트 `4780`을 입력한다.
3. `실행 중인 프로젝트 서버 자동 연결`을 켠다.
4. 서버 코드 폴더를 선택한다.
5. `더미 응답 연결`을 누른다.
6. 종료 확인창의 PID, 폴더, 실행 명령을 확인한 후 승인한다.

기대 결과:

- 사용자가 승인하기 전에는 기존 서버를 종료하지 않는다.
- 기존 서버가 `7777`에서 종료된다.
- DataForge가 `7777` 포트를 사용한다.
- 프로젝트 서버가 `7778` 포트에서 다시 실행된다.
- 화면 상태가 `더미 응답 연결됨`으로 변경된다.

### TC-403 더미 및 실제 서버 전달

자동 연결 상태에서 다음 요청을 보낸다.

1. 더미가 등록된 `/api/mock-target`
2. 더미가 등록되지 않은 `/api/real-target`

기대 결과:

- 첫 요청은 DataForge에 저장된 응답을 반환한다.
- 두 번째 요청은 `7778`의 실제 서버 응답을 반환한다.
- 클라이언트 요청 주소는 계속 `7777`을 사용한다.

## 8. 연결 진단

### TC-501 정상 상태

1. 자동 연결을 정상적으로 시작한다.
2. `연결 상태 자세히 보기`를 누른다.

기대 결과:

- 프로젝트 요청: 정상, `7777`
- 더미 응답: 정상, `4780`
- 프로젝트 서버: 정상, `7778`
- 원래 서버 복구: 준비됨, `7777`

### TC-502 프로젝트 서버 연결 실패

1. 잘못된 실행 명령 또는 열리지 않는 이동 포트로 연결을 시도한다.

기대 결과:

- 프로젝트 서버 단계가 오류로 표시된다.
- 서버 코드 폴더 또는 실행 방법을 확인하라는 안내가 표시된다.
- 전체 상태가 `확인이 필요합니다`로 표시된다.

### TC-503 수동 서버 방식

1. 자동 연결을 끈다.
2. 프로젝트 서버를 `7778`에서 직접 실행하지 않은 채 연결한다.
3. 서버를 `7778`에서 직접 실행한다.

기대 결과:

- 실행 전에는 `7778 포트로 실행해 주세요`라고 표시된다.
- 실행 후 다음 자동 새로고침에서 정상으로 변경된다.

## 9. 최근 요청

### TC-601 요청 기록 분류

더미 응답, 실제 서버 전달, 실패 요청을 각각 보낸다.

기대 결과:

- 최신 요청이 위에 표시된다.
- 메서드, 경로, 시간, 상태 코드, 처리 시간이 표시된다.
- 결과가 `더미 응답`, `실제 서버`, `실패`로 구분된다.
- 더미 응답에는 실제 선택된 응답 라벨이 표시된다.
- 실패 요청에는 원인이 표시된다.
- CORS 사전 요청인 OPTIONS는 목록에서 제외된다.
- 최대 10개만 화면에 표시된다.

### TC-602 한글 응답 라벨

1. 한글 라벨을 가진 응답을 등록한다.
2. 해당 응답을 사용하는 요청을 보낸다.

기대 결과:

- 요청이 HTTP 헤더 오류 없이 처리된다.
- 최근 요청에 한글 라벨이 정상 표시된다.
- DataForge 내부 추적 헤더가 클라이언트 응답에는 노출되지 않는다.

## 10. 연결 해제와 복구

### TC-701 정상 연결 해제

1. 기존 `7777` 서버를 자동 전환한다.
2. `연결 끊기`를 누른다.

기대 결과:

- DataForge가 `7777`을 해제한다.
- DataForge가 실행한 `7778` 서버가 종료된다.
- 기존 프로젝트 서버가 `7777`에서 다시 실행된다.
- 기존 서버가 없었던 경우에는 새 서버를 임의로 실행하지 않는다.

### TC-702 앱 종료 복구

1. 자동 연결 상태를 만든다.
2. macOS에서는 `Cmd + Q`, Windows에서는 창 닫기로 앱을 종료한다.

기대 결과:

- 프록시와 이동 서버를 먼저 정리한다.
- 기존 서버가 `7777`에서 복구된 후 DataForge가 종료된다.
- 종료가 중복 실행되거나 앱이 멈추지 않는다.

### TC-703 연결 실패 자동 복구

1. 기존 서버를 `7777`에서 실행한다.
2. 잘못된 이동 포트 또는 실행 명령으로 자동 전환을 시작한다.

기대 결과:

- 연결 실패를 감지한다.
- 일부 실행된 DataForge 서버를 정리한다.
- 기존 프로젝트 서버를 `7777`에서 다시 실행한다.
- 복구 성공 또는 직접 실행 필요 여부를 사용자에게 알린다.

## 11. 운영체제별 점검

### TC-801 macOS

- Intel과 Apple Silicon에서 각각 확인한다.
- `lsof`로 포트 사용 프로세스를 탐색한다.
- unsigned 배포 폴더의 `open.mac.command`로 실행한다.
- `Cmd + Q` 종료 복구를 확인한다.
- 경로에 공백이나 한글이 있는 서버 폴더를 확인한다.

### TC-802 Windows

- `netstat`으로 LISTENING PID를 탐색한다.
- 종료 확인 후 해당 PID만 종료되는지 확인한다.
- DataForge가 실행한 프로세스 트리가 연결 해제 시 정리되는지 확인한다.
- 창 닫기 후 원래 서버가 복구되는지 확인한다.
- 경로에 공백이나 한글이 있는 서버 폴더를 확인한다.

## 14. 완료 기준

- 필수 정상 흐름인 TC-101, TC-202, TC-402, TC-403, TC-501, TC-601, TC-701이 모두 통과한다.
- 서버를 종료한 뒤 복구하지 못하는 실패가 없다.
- DataForge 또는 프로젝트 서버 프로세스가 연결 해제 후 남지 않는다.
- macOS와 Windows에서 치명적인 실행 오류가 없다.
- 실패 상황에서 사용자가 다음 조치를 이해할 수 있는 안내가 표시된다.
